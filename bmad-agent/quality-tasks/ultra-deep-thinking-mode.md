# CRITICAL TASK: Ultra-Deep Thinking Mode (UDTM) - Mandatory Quality Protocol

## CRITICAL SAFETY RULES (MANDATORY COMPLIANCE)

### RULE 0 (MOST IMPORTANT): Analysis Integrity Protocol
If ANY phase yields <90% confidence, you MUST:
1. **STOP** all forward progress immediately
2. **DOCUMENT** specific uncertainty points
3. **RE-EXECUTE** the entire phase with additional data
4. **ESCALATE** if confidence remains low

**PENALTY**: Proceeding with low confidence = -$1000 penalty + mandatory reanalysis of ALL dependent decisions

### RULE 1: Anti-Pattern Detection
**NEVER PROCEED** if these patterns detected during analysis:
- Confirmation bias in evidence selection
- Cherry-picking favorable data points
- Assumption stacking (>3 levels deep)
- Circular reasoning in verification
- Emotional decision drivers
- Time pressure compromises

### RULE 2: Evidence Requirement
**ALL** analysis conclusions MUST have:
- Minimum 3 independent evidence sources
- Quantitative backing where possible
- Documented confidence intervals
- Clear traceability to sources
- Explicit limitation statements

## PURPOSE (MANDATORY UNDERSTANDING REQUIRED)
Execute rigorous, multi-angle analysis and verification protocol to ensure highest quality decision-making across all BMAD personas. This UDTM protocol is NON-NEGOTIABLE for all major decisions.

## WHEN UDTM IS MANDATORY
- **ALWAYS** for architectural decisions
- **ALWAYS** for technology selections
- **ALWAYS** for user story creation
- **ALWAYS** for quality gate definitions
- **NEVER** skip for time pressure
- **NEVER** abbreviate phases

### Phase 1: Multi-Angle Analysis (35 minutes MINIMUM)
**MANDATORY PERSPECTIVES** (all must be explored):

1. **Primary Domain Analysis**
   - [ ] Core functional requirements
   - [ ] Technical constraints and capabilities
   - [ ] Performance implications
   - [ ] Security considerations
   - [ ] Scalability factors
   
2. **Cross-Domain Integration**
   - [ ] System-wide dependencies
   - [ ] Interface requirements
   - [ ] Data flow implications
   - [ ] Integration complexity
   - [ ] Version compatibility

3. **Stakeholder Impact Assessment**
   - [ ] End-user experience effects
   - [ ] Developer workflow changes
   - [ ] Operations team implications
   - [ ] Business cost/value analysis
   - [ ] Compliance requirements

4. **Risk and Mitigation Analysis**
   - [ ] Technical failure modes
   - [ ] Business continuity risks
   - [ ] Security vulnerabilities
   - [ ] Performance degradation scenarios
   - [ ] Recovery strategies

5. **Alternative Solutions Exploration**
   - [ ] Minimum 3 alternatives documented
   - [ ] Pros/cons matrix completed
   - [ ] Trade-off analysis performed
   - [ ] Selection rationale explicit
   - [ ] Rejected options documented

6. **Long-term Evolution Perspective**
   - [ ] 6-month implications
   - [ ] 1-year sustainability
   - [ ] 3-year technical debt
   - [ ] Migration path clarity
   - [ ] Sunset strategy defined

**PHASE 1 GATE**: Cannot proceed unless ALL perspectives have substantive analysis

### Phase 2: Assumption Challenge Protocol (15 minutes STRICT)
**ZERO TOLERANCE for unchallenged assumptions**

1. **Assumption Inventory** (5 minutes)
   ```markdown
   ## Explicit Assumptions
   - [List every stated assumption]
   
   ## Implicit Assumptions  
   - [List unstated but required assumptions]
   
   ## Environmental Assumptions
   - [List context-dependent assumptions]
   ```

2. **Systematic Destruction** (5 minutes)
   For EACH assumption:
   - Attempt to disprove it
   - Find counter-examples
   - Identify edge cases
   - Document fragility level
   - Create mitigation plan

3. **Evidence Validation** (5 minutes)
   - Source verification required
   - Recency check (<6 months preferred)
   - Relevance confirmation
   - Confidence scoring (0-100%)
   - Alternative evidence search

**PHASE 2 GATE**: >90% assumptions validated with evidence OR explicit risk acceptance

### Phase 3: Triple Verification Protocol (25 minutes MANDATORY)

**Source 1: Primary Evidence** (10 minutes)
- [ ] Official documentation reviewed
- [ ] Source code examined (if applicable)
- [ ] Vendor specifications confirmed
- [ ] Performance benchmarks verified
- [ ] Security audits checked

**Source 2: Pattern Analysis** (10 minutes)
- [ ] Historical success/failure patterns
- [ ] Industry best practices reviewed
- [ ] Similar implementation analysis
- [ ] Anti-pattern recognition completed
- [ ] Lesson learned integration

**Source 3: External Validation** (5 minutes)
- [ ] Expert consultation (if available)
- [ ] Community feedback reviewed
- [ ] Independent benchmarks consulted
- [ ] Third-party assessments considered
- [ ] Regulatory compliance verified

**VERIFICATION SYNTHESIS**
- [ ] All sources corroborate (>80% alignment)
- [ ] Discrepancies explicitly addressed
- [ ] Confidence level calculated
- [ ] Limitations documented
- [ ] Decision defensibility confirmed

**PHASE 3 GATE**: Triple verification achieved OR explicit exception documented with mitigation

### Phase 4: Weakness Hunting Protocol (15 minutes CRITICAL)
**MANDATORY negative thinking exercise**

1. **Blind Spot Identification**
   - What haven't we considered?
   - What expertise are we missing?
   - What context might change?
   - What dependencies are hidden?
   - What assumptions are invisible?

2. **Failure Mode Analysis**
   - How could this fail catastrophically?
   - What cascade failures are possible?
   - What's the blast radius of failure?
   - How would we detect failure?
   - What's the recovery plan?

3. **Bias Recognition**
   - Confirmation bias check
   - Recency bias evaluation
   - Authority bias assessment
   - Groupthink indicators
   - Sunk cost influence

4. **Edge Case Exploration**
   - Extreme load scenarios
   - Unusual user behaviors
   - Rare error conditions
   - Concurrent conflict cases
   - Resource exhaustion scenarios

5. **Mitigation Planning**
   - For each weakness found:
     - Document specific risk
     - Assess probability/impact
     - Design mitigation strategy
     - Define monitoring approach
     - Create contingency plan

**PHASE 4 GATE**: All critical weaknesses have mitigation plans

## ERROR RECOVERY PROCEDURES

### When Confidence Drops Below 90%:
1. **IMMEDIATE STOP** - Do not proceed
2. **IDENTIFY** specific uncertainty sources
3. **GATHER** additional evidence
4. **RE-EXECUTE** affected phases
5. **ESCALATE** if still uncertain

### When Time Pressure Conflicts:
1. **DOCUMENT** pressure source
2. **COMMUNICATE** quality risks
3. **NEGOTIATE** scope reduction
4. **NEVER** compromise phases
5. **ESCALATE** to leadership

### When Evidence Conflicts:
1. **STOP** current analysis
2. **DOCUMENT** all conflicts
3. **INVESTIGATE** root causes
4. **WEIGHT** evidence by reliability
5. **DECIDE** with explicit rationale
